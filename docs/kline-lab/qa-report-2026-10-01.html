一句话结论

功能本身是好的：两个内核的周期切换、主副图指标、缠论叠加、时间轴定位、快捷键、主题、响应式 在真机上全部工作，7 个市场标的里有 5 个完全正常。

但容错层很薄 —— 表现最好的三项全是"出错之后怎么办"：一次图表重建会让整个终端页白屏； 港美股和写错的代码会永远显示"载入中"；盘口取不到时会反复弹红条。 换句话说：正常路径没问题，异常路径会暴露给用户。这 6 项已修，剩下 4 项涉及产品取舍，等你拍板。

测试范围与方法

双内核功能
ECharts 20 项 + KLinePro 15 项：周期档（日/周/月/分钟）、复权、主图指标、副图指标、 指标管理面板、缠论笔/中枢、定量结构、信号/触发/回测叠加、事件时间轴与点击定位、6 个快捷键、三档响应式。
边界与健壮性
深主板 / 沪主板 / 科创 / 创业 / 北交所 / 港股 / 美股 七个标的； 无效代码；连续切内核 6 次；连续换股 5 次；亮暗主题；键盘可达性与 aria。
方法要点
断言不只看"有没有报错"，还看画面是否真的变了（canvas 内容指纹）与 是否真的画了东西（像素油墨占比）。导航后校验落地标的，避免跑错页面得出假结论。

已修复缺陷（6）

严重 图表重建时整个终端页白屏 已修

现象
个股终端页静置几秒后，整页被替换成一段红色堆栈——侧栏、顶栏、图表全部消失，只能手动刷新。Cannot read properties of null (reading 'on')
复现
100% 可复现，且触发条件与"页面高度变化"绑定：窗口高度剧变、开关开发者工具、缩放页面都会命中。普通窗口宽度拖拽不触发。
根因
StockDailyKChart.tsx 的画线 effect 里只守了 chart，没守 chart.getZr() 的返回值。echarts 5.6.0 的 dispose() 会把实例内部的 _zr 置为 null，在"旧实例已销毁、新实例还没写回 state"的窗口期里就是 null，挂监听立刻抛错。
修复
补 if (!zr) return 守卫（并写清了为什么必须守）。
验证
同一复现路径下 3 次截图全部通过，异常数 0。
// frontend/src/components/StockDailyKChart.tsx
const zr = chart.getZr()
// ★ chartInst 可能是已 dispose 的实例: echarts 5.6.0 的 dispose() 会把 _zr 置 null
if (!zr) return

严重 任何渲染异常都会整页白屏，没有出口 已修

现象
上面那条崩溃之所以"致命"，是因为 React Router 用了内置错误页：整屏只剩堆栈，连"返回"按钮都没有，用户唯一出路是刷新。
修复
新增路由级兜底页（错误摘要 + 重新加载 + 回首页），挂在根路由上由所有子路由继承。今后单页出错不再拖垮整个应用。

中 按 Esc 被退回上一只股票 已修

现象
在 KLinePro 里打开"指标"面板，按 Esc 想关面板 —— 结果被送回上一只股票。面板纹丝不动地留着，页面已经换了标的。
根因
StockTerminal.tsx 的 Esc 分支是 navigate(-1)；而"关闭浮层"的白名单只包含命令面板/帮助/监控设置，指标面板不在其中，于是 Esc 直接落到"后退"。
修复
面板根节点加 data-overlay-panel 标记并自己接管 Esc（关闭自己）；终端层看到该标记就让路、不后退。语义回到"Esc = 关掉当前浮层"。
副作用
无标记时 Esc 仍然保留"返回上一页"的原行为。

中 港股/美股顶栏永远"载入中…" 已修

现象
00700.HK 主图渲染完全正常，但顶栏价格永远是 — 且状态挂"载入中…"，盘口面板同步转圈。实测 12 秒持续不变。
根因
港美股没有五档盘口，/api/depth 返回 404。react-query v5 在"无数据 + 定期轮询"下会把查询周期性带回 pending，于是 isLoading 长期为真——那句早就写好的兜底文案"盘口不可用 · 以图表为准"永远没机会显示。不是没做降级，是降级被"加载中"盖住了。
修复
用 failureCount 记住"失败过"：一旦失败就不再声称加载中。顶栏与盘口面板同一口径。现在 4 秒内落到稳定降级态。

中 盘口取不到时红色 toast 刷屏 已修

现象
无效代码/港美股页面上，右下角反复弹出"未获取到 XXX 的盘口数据"，实测 12 秒弹 3 条。
根因
API 层的统一错误处理对每个非 2xx 响应都弹 toast。这对一次性操作是对的，对 6 秒一轮的盘口轮询就是刷屏。
修复
盘口请求改为静默（quiet: true）——UI 已有文案表达"不可用"，不需要再弹。验证后 toast 数为 0。

低 既有验收脚本"假绿" 已修

现象
run-terminal-check.mjs 一直是 PASS，但它连"当前跑在哪个内核上"都没锁定过。
根因
脚本写入的 localStorage 键是 tickflow-kline-pro，而代码实际读的是 tickflow.useKLinePro —— 那个键没有任何代码读取，"锁定从 ECharts 开始"从未生效，测试实际跑在哪个内核完全取决于上一次残留。另外它注释里的 T3 从未实现，等待条件还会被无关文本提前满足。
修复
键名修正为真实键；新增正式测试套件（见下），断言全部改为"落地校验 + 画面指纹 + 像素油墨"。

待你决策（4）

中 ECharts 内核没有指标管理入口

现状
KLinePro 侧有完整的指标面板（27 个内置指标可加、可改参数、可删）；ECharts 侧顶栏根本没有"指标"按钮，写死 MA + BOLL + 定量结构 + 成交量，用户无法换成 MACD/KDJ 副图。
影响
这正是你最初说的"切换两个看板割裂"里最实的一块——不是观感，是能力不对等。切到 ECharts 就失去了配指标的能力。
建议
两条路：① 给 ECharts 侧补同款指标面板（工作量大，ECharts 的副图都是手写 series）；② 明确 ECharts 定位为"轻量/兼容内核"、KLinePro 为"主内核"，在能力矩阵里把这条差异显式化并在 UI 上提示。我倾向 ②，成本低且诚实。

中 无效标的时 K 线区是一片纯空白

现状
访问不存在的代码时，顶栏和盘口现在会正确显示"不可用"，但 K 线区域是一个没有任何文字的灰底空框（KLinePro 内核下会显示"暂无该周期数据"，ECharts 内核下什么都没有）。
建议
补一个统一空态："未找到该标的的数据" + 一句原因提示。改动落在渲染分支，回归面中等，建议单独一次提交。

中 裸代码进入终端会静默全空

现状
手工把地址改成 /stock/000001（不带 .SZ）时，后端返回 200 + 空数组，前端因此把它当成"这只票没数据"，页面全空且没有任何错误提示。
根源
三处叠在一起：前端直接把路由参数当代码用、不补市场后缀；后端推导不出市场时静默返回空；盘口则返回 404。同一个问题三种表现。
建议
前端按代码前缀补后缀（6/9→SH，0/2/3→SZ，4/8/92→BJ），匹配不到再提示"代码格式有误"。这是纯前端、低风险的改法。站内入口都带后缀，所以只影响手工输入。

低 /api/depth 用 404 表达"这个市场没有盘口"

现状
港美股、无效代码、格式错误全部返回 404 + 同一句 detail。调用方无法区分"标的不存在""这个市场不提供盘口""参数写错了"。
建议
区分语义：市场不支持 → 200 + 空快照（前端天然降级）；标的不存在 → 404；参数非法 → 422。属后端改动，需要重启后端。
